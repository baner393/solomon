# 架构

solomon 是一套「**确定性管线**」：把视频/文档加工成结构化知识库，再对知识库做语义问答。
核心设计决策是——**所有加工步骤是脚本，不是 agent 自由发挥**，因此可断点续跑、可重放、可回退。

## 总体分层

```
┌────────────────────────────────────────────────────┐
│                   用户入口 (CLI)                    │
│   solomon ingest / ask / doctor / init / verify    │
├────────────────────────────────────────────────────┤
│   pipeline/       入库管线（确定性脚本）            │
│   query/          问答侧（FTS5 + LLM 综合）         │
│   assets/         辅助脚本（关键帧/识图/标注/verify）│
├────────────────────────────────────────────────────┤
│   知识库 vault（Obsidian 格式，用户私有）           │
│   raw/ concepts/ entities/ comparisons/ queries/   │
└────────────────────────────────────────────────────┘
```

- **代码与数据分离**：代码在仓库内，vault 默认在 `~/.solomon/vault`（可用 `.env` 指到任意位置）
- **索引随 vault 走**：FTS5 索引与查询缓存放 `vault/.kb/`，每个知识库独立，绝不串库
- **LLM 只做内容生成，其余全脚本**：检索、入库、索引、校验都是确定性代码

## 入库管线（ingest）

```
输入形态 → 形态识别 → 内容提取 → LLM 笔记 → 五层提炼 → 入库 → postprocess
```

### 视频（核心）

```
下载(yt-dlp / B站API兜底)
  → 字幕(B站AI字幕 → sherpa-onnx 转写 → 纯视觉降级)
  → 关键帧(MAR 场景检测 + dHash 去重)
  → 识图(SenseNova/LLM 视觉, 并发)
  → 笔记(LLM; >20min 长视频按时间窗分段生成后合并)
  → 五层提炼(9 段模板 + 视频类型动态占比)
  → 入库(图文结合: 关键帧按 where 锚点穿插正文)
  → postprocess(FTS5 索引/相关页推荐/index/log/verify)
```

关键特性：
- **断点续跑**：每步产物落盘，存在则跳过（`--force` 全量重跑）
- **合集/分P**：探测 ugc_season / pages>1，每分集独立处理 + 合并笔记 + 一份五层（`--max-parts N` 限集数）
- **多模态交叉验证**：字幕片段 × 关键帧按时间窗确定性配对，笔记里做语义核对
- **音频信号检测**：停顿/重复/语速 → 💡/🔥/⏩ 标记注入笔记
- **标注截图**：操作类视频关键帧自动红框标注
- **质量门槛**：CHECKPOINT B 按时长算 min 图/字数，不达标自动重生一次

### 文档（md/txt/pptx/…）

```
提取文本 → LLM 生成标题 → 存 raw 原文 → 建 wiki 骨架页 → postprocess
```

### 视频类型 → 模板

`assets/SKILL_TEMPLATES/` 按类型（知识讲解/操作教程/公考行测/英文技术…）定义笔记结构，
`ingest` 自动识别类型选模板，未识别回落默认中文技术教程。

## 问答侧（query）

```
问题 → jieba 分词拆词 → FTS5 trigram 检索（top-N）
     → LLM 综合回答（结论/依据/延伸，引用真实页面）
     → 语义缓存（相同问题 24h 内秒回；KB 指纹变化自动失效）
```

- 中文分词：FTS5 trigram 天然支持 ≥3 字串；jieba 拆自然问句为有效词 OR 匹配
- `--raw` 模式只检索不调 LLM（调试/快查用）
- 检索失败自动降级 LIKE 兜底

## 配置

所有可配置项集中在 `src/solomon/config.py`，加载顺序（后者覆盖前者）：
**代码默认值 → 仓库 `.env` → 系统环境变量**。新用户零配置可跑（默认本地 LLM 端点），
个人化项（vault 路径/LLM 端点/代理）写在 `.env`（gitignore）。

## 与 Hermes 的关系（可选集成层）

solomon 核心不依赖 Hermes（纯 Python 进程）。可以把它接进 Hermes 做渠道化
（QQ/飞书发 `@newsolomon` 入库、`@solomon` 问答），见 `profiles/` 与 `patches/`。

## 为什么不用 RAG 框架

FTS5 + LLM 综合对个人知识库（百页级）足够，且零框架依赖：
- 无向量库运维负担（一个 SQLite 文件）
- 检索透明可调试（`--raw` 直接看命中）
- 中文场景 trigram + jieba 效果好、快（百页毫秒级）

若未来知识库到万页级再评估向量检索，届时 llm/检索层已隔离可替换。
